# rulii-explorer — Claude Code Project Guide

## Project Overview

- **Name**: rulii-explorer — browse, search and visualise the rules, rule sets and rule flows of a running rulii application
- **Version**: 1.0.0-SNAPSHOT (Maven coordinates `org.rulii:rulii-explorer-*`)
- **Java**: 17
- **Build**: Maven, multi-module. No Node or npm anywhere: the UI is static files.
- **License**: Apache 2.0
- **Depends on**: rulii 2.1.0-SNAPSHOT, rulii-spring 2.1.0-SNAPSHOT (the 2.1 introspection API), Spring Boot 4.1.x / Spring Framework 7.0.x, Jackson 3, JUnit Jupiter 6. Versions come from the Spring Boot BOM imported in the parent POM.
- **Design docs**: `docs/REQUIREMENTS.md`, `docs/SOLUTION.md`, `design/` (the approved visual design; `design/tokens.css` is the source of truth the UI module copies in M3) and `mockups/` (obsolete, never a baseline) are all local-only: gitignored and untracked, kept on Max's machine.

## Coding Style

- **License header**: every source file (main and test) starts with the Apache 2.0 block. Copy from any existing file.
- **Explicit `super()` in every constructor**, as in rulii.
- Javadoc on public types and methods; `@author Max Arulananthan`, `@since 1.0`.
- Descriptor output must be stable: fixed key order, arrays sorted by type then ID, no timestamps in the body.

## Build & Test

```bash
mvn install                 # whole reactor, runs tests
mvn -pl rulii-explorer-core test
mvn -pl rulii-explorer-demo spring-boot:run   # http://localhost:8080/rulii and /actuator/rulii (the demo exposes health,rulii)
mvn -pl rulii-explorer-ui test                # browser tests; the first run downloads Chromium (~150 MB) into the Playwright cache
mvn -pl rulii-explorer-ui test -Dscreens.update=true   # rewrite the screenshot baselines after an intended visual change
```

On Windows via PowerShell: `powershell.exe -Command "Set-Location 'C:\\Dev\\rules\\rulii-explorer'; mvn install 2>&1"`.

The rulii and rulii-spring snapshots must be installed locally first (`mvn install -DskipTests` in each), from their `feature/explorer-introspection` branches.

## Key Contracts

- **Descriptor**: one versioned JSON document (`descriptorVersion` = `Explorer.DESCRIPTOR_VERSION`). The JSON Schema in core (`rulii-descriptor-1.schema.json`) is the contract; SOLUTION.md §5 is the sketch it grew from. Golden file: `rulii-explorer-core/src/test/resources/golden/java-fixture.json`, validated against the schema; regenerate with `mvn -pl rulii-explorer-core -Dtest=DescriptorJsonTest -Dgolden.update=true test` and review the diff.
- **Builder rules**: artifact ids are registry names; inline members/targets get path ids (`x/members[2]`, `flow/commands[3]/target`) with `registered=false`. Rulii's own hooks (default rule set extractor/handler, the validating check) are hidden; a predefined validator is described by its `validation` section only; a supplied validation rule shows the supplied condition. Lists sort naturally (`commands[2]` before `commands[11]`).
- **SpEL analysis**: `Placeholders` pre-pass (`${k:d}` becomes `#__phN`, never resolved), `SpelTranslator` AST walk through the `Phrases` phrase book, raw tokens for anything else (`T()`, `@bean`, projections, unknown `#vars`). Golden corpus: `rulii-explorer-core/src/test/resources/golden/spel-corpus.md` (Markdown table, regenerate with `-Dtest=SpelExpressionAnalyzerTest -Dgolden.update=true`). Add phrases to `Phrases`, add every new case to the corpus.
- **Endpoint**: Actuator id `rulii` → `GET /actuator/rulii`, read-only, opt-in via `management.endpoints.web.exposure.include`. `WebEndpointResponse` carries no headers, so ETag/Last-Modified are not sent by the Actuator endpoint; `DescriptorService.Snapshot` has `etag()`/`builtAt()` for the UI handlers (M3). Starter tests: `src/test/resources/application.properties` excludes Spring Security auto-config (the security test clears the exclusion) and pins `spring.main.web-application-type=servlet` (the WebFlux test sets `reactive`); tests use the JDK `HttpClient`, since Boot 4 dropped `TestRestTemplate` from `spring-boot-starter-test`.
- **UI serving**: page at `rulii.explorer.ui.path` (default `/rulii`, also with a trailing slash) rendered by `UiPage`, which rewrites every `"./` in `index.html` to `{contextPath}{path}/{explorer version}/` and sets the `rulii-descriptor` meta to `{contextPath}{management base path}/rulii`; assets only under the versioned path, cached a year immutable (raw `/rulii/index.html` is 404). The path segment is `UiPage.assetSegment()`: the plain version for releases, `{version}-{jar timestamp base36}` for `-SNAPSHOT`/`dev` builds, so every rebuild busts the browser cache (an M4 bug: identical SNAPSHOT paths served stale M3 files until a hard reload). `rulii.explorer.ui.enabled=false` removes both. Never put UI files under `META-INF/resources` (Boot would serve them unversioned). The same-port configurations are `@Import`ed by the auto-config and must not use `@ConditionalOnBean(UiPage)` (evaluated before the `@Bean` registers); the management-context ones may. Bean names must not collide with `ruliiExplorerUiPage`.
- **UI code**: Lit elements render into the light DOM (`RxElement` in `app/components/base.js` subscribes to the store); all styling lives in `app/design/app.css` with `rx-` classes taken from the approved screens. Hash routes: `#/`, `#/problems?severity=`, `#/rule|ruleset|ruleflow/{id}` (`?step=commands[1].body[0]` highlights an outline step), `#/binding/{name}`, `#/package/{id}`. `descriptor/indexes.js` builds every lookup once; `descriptor/summaries.js` writes the italic sentences and problem explanations and never guesses (compiled code says so); `search/search.js` is the field-weighted search. SVG fragments inside templates use Lit's `svg` tag, `<svg>` roots use `html`. Keyboard: Ctrl/⌘ K or `/` opens the palette, Tab cycles its type filter. Graph buttons and the Flowchart/Graph tabs are present but inert until M4.
- **Properties**: `rulii.explorer.enabled` (default false: the explorer is opt-in so production never shows rules by accident; the demo and the starter tests set it to true in their `application.properties`), `rulii.explorer.ui.enabled`, `rulii.explorer.ui.path`, `rulii.explorer.include-sources`, `rulii.explorer.application-name`.
- **Sources**: the explorer reads only `RuleRegistry` and each artifact's definition. rulii-spring stamps XML-built artifacts with `SourceDefinition.forFile(location, line)`; class-based rules report their rule class; Java-built artifacts report the `@Bean` method or builder call site.
- **Graph rendering (M1 spike, `rulii-explorer-ui/spike/RESULTS.md`)**: SVG + d3, but pan/zoom is a CSS `transform` on the SVG layer (compositor), re-rendered sharp on zoom end; never a transform attribute on an inner `<g>` (repaints every frame). Dependency graph: ELK `POLYLINE` routing + `BRANDES_KOEPF` placement above 200 nodes (0.7 s for 1,000), `ORTHOGONAL` + `NETWORK_SIMPLEX` below; flowchart: always `ORTHOGONAL`. No canvas edges.
- **Graphs (M4)**: `app/graph-engine/` = `vendor.js` (lazy `<script>` loading of d3 and ELK relative to the module URL, text measuring), `layout.js` (ELK adapter, layout cache keyed per view + inputs, `absolutePositions`, `roundedPath`), `stage.js` (`GraphStage`: d3-zoom on the stage div, CSS transform on the SVG, fit/zoomBy/centerOn, minimap). `features/graph/` = `graph-model.js` (nodes incl. `missing:<name>` targets from unresolved lookups, `focusGraph` BFS by depth, `filterGraph`, `toElk` with package compound nodes), `graph-render.js` (d3 drawing, hover dims non-neighbours, selection ring), `graph-aside.js`, `graph.js` (`rx-graph` page at `#/graph?focus=&depth=&selected=`). `features/flow/` = `flow-model.js` (one node per command, decisions for when/for-each, containers for scope and loop bodies, async steps + handlers form the lane, `await` joins via its `as` names, exits are terminal), `flowchart.js` (`rx-flowchart` element), `step-aside.js` (the selected-step panel shared with the outline; `resolveStep` understands `commands[..]`, `handler:<path>`, `global`). The flow page defaults to `?view=flowchart`; `?view=outline` is the text equivalent; `?step=` is the shared selection. d3 attributes must never receive Lit's `nothing` (a Symbol): use null. **Scale rules (M5):** `GROUP_LIMIT` = 200 in `graph.js`: above it the whole-application view uses the flat layout (ELK's compound layout takes minutes at 1,000 nodes) and `dependencyOptions` switches to the spike's lean polyline settings (model-order constraints and component separation multiply the time by 20); `GraphStage.fit` never goes below `minFit` 0.45, so a huge drawing opens readable at its top-left; the overview map lists at most 24 rule sets. Components that render into a canvas must bail out when the route is not theirs (`rx-graph` checks `route.name`), or they lay out on the way out.
- **Accessibility (M5)**: `BrowserTest` injects axe-core (test-only, `src/test/resources/vendor/axe`, MPL-2.0) into every screen and fails on serious/critical WCAG 2.1 A/AA violations; `keyboardOnlyPath` drives the palette, tabs through the outline page and selects a graph node by keyboard. Rules learned: containers with focusable children get `role="group"`, not `role="img"`; the minimap is `aria-hidden`; outline footers need their own `role="tree"`; tertiary ink (`--rx-ink-3`) is not readable on the selected fill, so selected rows use `--rx-ink-2`, and palette match marks are ink with an accent underline.

## Release

- `mvn -P release deploy` signs (GPG, `--pinentry-mode loopback`) and publishes via `central-publishing-maven-plugin`. The demo module skips deploy, javadoc, sources and signing.
- **1.0.0 checklist**: (1) release rulii 2.1.0 and rulii-spring 2.1.0 first and point `rulii.version` / `rulii-spring.version` at them (the explorer fails on older versions); (2) set the reactor version to 1.0.0 (`mvn versions:set`), which also makes `UiPage.assetSegment()` the plain version; (3) `mvn install` green incl. browser and scale tests; (4) CHANGELOG.md dated; (5) THIRD-PARTY-NOTICES.md and vendor/README.md match the vendored files; (6) README version in the dependency snippet; (7) `mvn -P release deploy`; (8) tag `v1.0.0`; (9) back to the next SNAPSHOT.
